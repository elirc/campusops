# Hint ladders for chapters 03 through 10

For the reservation ledger, label the candidate snapshot separately from the stored part. A caller's original object is another distinct instance. The publication gate matters only to readers that use the same authority. For the timeline proposal, first decide whether inventory reservation history and work-order events are one required commit or two views with a documented delay.

For cancellation, place the token check on the stage diagram. There is no later store check after publication. A canceled token observed after a successful call is not evidence that the call failed. Separate abandoning a transport wait from releasing an accepted business allocation.

For duplicate analysis, compare the identity used by AddAsync with the identity generated by ReserveForWorkOrderAsync. Equal request fields can express a new allocation or a retry; the store cannot infer intent without another contract. A receipt lookup must participate in the same coordination as publication to prevent two simultaneous first attempts from both winning.

For concurrency, map each assertion to a different failure. Five successful results alone do not prove five matching records. A current snapshot outside the gate is only an observation, while the store command reads current authoritative stock inside it. A per-part optimization must still explain shared history and stable lock identity.

For work orders, separate EnsureVersion from the following mutation. A successful comparison does not hold a version open for later use. Read Cancel's allowed states and retained fields directly rather than assuming it clears every property. The existing concurrency-named test checks a sequential stale value, so identify the additional schedule needed for a stronger claim.

For conversion, mark the moment the request becomes Converted and the later moment the order is added. A local candidate with a GUID is not a stored order. For location integrity, compare request submission's dependencies with AssetService.CreateAsync; one can load a location and the other does not. A nonempty ID is not proof of referential existence.

For technician ownership, inspect the runtime object returned through the read-only interface. Then distinguish a local in-process cast from a remote JSON request. For assignment authority, locate the exact endpoint mapping and its metadata rather than assuming a URL prefix inherits another group's policy.

For comments, draw two queues and two separate appends. A failure before the second append leaves the first record intact. Timestamp proximity does not create an explicit link between the records, and an Author string supplied by the client is not automatically the verified actor. Decide which evidence the word audit is supposed to promise.
