# Learner guide

CampusOps targets a junior engineer moving toward mid-level ownership. Work through sprint documents in order, read the corresponding pull request, run the nearest tests, and explain each design choice in plain language.

For every sprint:

1. Read the outcome and acceptance criteria.
2. Draw the request path from contract to use case to adapter.
3. Predict failure cases before reading tests.
4. Run focused tests, then the whole solution.
5. Review what was deliberately not abstracted.

The goal is protecting business rules, publishing dependable contracts, and making changes with evidence.
